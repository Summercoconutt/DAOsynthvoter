SERVER RUNBOOK — whole_pipeline (minimal)

IMPORTANT — use branch: carlo_dev
  git clone https://github.com/Summercoconutt/DAOsynthvoter.git
  cd DAOsynthvoter
  git checkout carlo_dev && git pull
  Do NOT use main for behaviour modelling; main is outdated relative to carlo_dev.

1. Copy whole_pipeline/ to the server. Do not rely on Windows paths (e.g. D:\...); edit YAML to Linux paths.

2. Python 3.10+, then:  pip install -r requirements.txt   (includes duckdb for stage 08b)

3. Every run:  export PYTHONPATH=/absolute/path/to/whole_pipeline/src

4. Point raw vote parquet(s) via configs — use absolute paths in a small override YAML merged with --extra-config (see configs/example_server_raw.yaml). Stage 03 writes ONLY under whole_pipeline outputs (never overwrites raw).

5. Order of sanity checks:
   - python scripts/10_run_detection_mode.py [--skip-raw-scan if raw dir absent]
   - python scripts/10_run_detection_mode.py --smoke-train   (tiny RoBERTa train; configs/smoke_behaviour.yaml)
   - Full stage 08 only after prerequisites pass (cleaned votes + dao_feature_table.csv).
   - python -m pytest tests/test_leakage_safe_pipeline.py -v   (20 tests, no GPU)

5b. LEAKAGE-SAFE Stage 8 (carlo_dev, 2026-07):
   - Stage 6/7 cluster CSVs are NOT used by stage 08.
   - Minimum: stage 03 (votes_cleaned.parquet) + stage 04 (dao_feature_table.csv).
   - See docs/SUPERVISOR_LEAKAGE_SAFE_GUIDE.md (detailed) and docs/LEAKAGE_SAFE_RUNBOOK.md (short).
   - Old Stage 08 models with feat_dim=10 are incompatible; retrain Stage 08. The current 08b baseline intentionally uses feat_dim=10.

6. RoBERTa behaviour training:
   scripts/08_run_behaviour_modelling.py --config configs/default.yaml  (+ optional --extra-config)

7. No-RoBERTa comparison (numeric-only baseline):
   scripts/08b_run_behaviour_modelling_no_roberta.py --config configs/default.yaml \
   --reuse-behaviour-csv --reuse-split-manifest
   See docs/SUPERVISOR_NO_ROBERTA_RUNBOOK.md for details.

8. GPU: install CUDA-matching PyTorch if needed. Smoke config limits epochs/windows for a quick pass.

9. Do not commit huge outputs/.venv; share code + configs only unless artefacts are required.
